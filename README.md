# H5 游戏作品集 - PixiJS Demo

面向 H5 游戏前端岗位的工程化 Demo，基于 PixiJS v8 + TypeScript 自研轻量框架开发。

## 技术栈

| 项 | 技术 |
|----|------|
| 渲染引擎 | PixiJS v8 |
| 语言 | TypeScript |
| 构建工具 | Vite |
| 架构 | 自研轻量游戏框架 |
| 音频 | Web Audio API（程序化生成音效） |

## 项目结构

```
src/
```

## 游戏一：星际战机（射击类）

### 核心功能
- **玩家控制**：鼠标/键盘双控制，自动射击，3条生命，受击无敌帧
- **武器系统**：单发/双发/三发火力，道具限时增强
- **敌机系统**：3种敌机（普通/快速/重型），对象池复用，血条显示
- **Boss 战**：2个 Boss，多阶段血量，扇形弹幕，入场动画
- **道具系统**：5种道具（双发/三发/护盾/回血/清屏炸弹）
- **碰撞检测**：圆形碰撞检测，统一碰撞管理器
- **难度递增**：随分数提升敌机生成速度和移动速度
- **粒子特效**：爆炸粒子、引擎尾焰、屏幕震动
- **快速展示**：初始 1400 分，30秒内可见 Boss；演示模式一键加速
- **数据持久化**：最高分存 localStorage

### 面试亮点
- 对象池模式（敌机/子弹复用，避免 GC 卡顿）
- 状态机（场景切换、游戏状态管理）
- 数据驱动（敌机属性、道具概率、难度曲线全部配置化）
- 性能优化（ParticleContainer、对象池、脏矩形）

## 游戏二：缤纷消消乐（三消类）

### 核心功能
- **棋盘系统**：8x8 网格，6种颜色，初始生成保证无可消除
- **交换逻辑**：点击选中→相邻交换→无效回弹
- **匹配算法**：横/纵三连检测，连锁消除递归
- **特殊方块**：四消→条纹方块（消整行/列）、五消→彩虹炸弹（消同色）
- **下落填充**：消除后下落、顶部补充、缓动动画
- **动画队列**：交换→消除→下落→补充，严格按序执行
- **连击系统**：连锁消除 Combo 计数，分数倍率
- **关卡系统**：5个关卡，目标分数+步数限制递增
- **道具系统**：锤子（敲单个）、洗牌、加5步
- **新手引导**：首关高亮可消除位置
- **规则说明**：选关页可展开游戏规则

### 面试亮点
- 匹配算法（横向+纵向扫描，去重处理）
- 动画队列管理（异步动画串行执行，防止状态错乱）
- 特殊方块合成逻辑（四消/五消/T形消除的判定）
- 死局检测与自动重排
- 数据驱动关卡设计

## 面试常见问题准备

### Q: 为什么用 PixiJS 而不是 Cocos / Phaser？
A: PixiJS 是轻量的 2D 渲染引擎，只负责渲染，不绑定游戏框架，灵活度高。对于 H5 小游戏来说，包体小、性能好、学习成本低。Cocos 更适合中大型项目，Phaser 功能全但较重。这个 demo 用 PixiJS 可以展示我对底层渲染和游戏架构的理解。

### Q: 对象池是怎么实现的？为什么要用？
A: 对象池预先创建一批对象，使用时取出，用完放回，避免频繁 new/destroy 导致的内存分配和 GC 卡顿。游戏中敌机、子弹、粒子都是高频创建销毁的对象，用对象池可以显著提升性能。实现上用一个数组存储空闲对象，acquire 取出，release 放回并重置状态。

### Q: 消消乐的匹配算法怎么实现的？
A: 分别做横向和纵向扫描。横向遍历每一行，统计连续相同颜色的长度，>=3 就记录为一个匹配。纵向同理。用一个 visited 集合去重，避免同一个方块被重复计算。匹配后递归检查连锁消除。

### Q: 动画队列怎么管理的？
A: 消消乐的动画有严格的顺序依赖：交换→消除→下落→补充→检查新匹配。用 async/await 把每个动画阶段封装成 Promise，按顺序 await 执行。动画期间锁定用户输入，防止状态错乱。

### Q: 游戏循环是怎么实现的？
A: 用 PixiJS 的 Ticker，每帧调用 update 方法，delta 参数是帧时间增量。所有游戏对象的位置更新、碰撞检测、状态机更新都在主循环里按顺序执行。每个场景有独立的 Ticker，场景切换时停止旧场景的 Ticker。

### Q: 音效怎么实现的？
A: 用 Web Audio API 程序化生成音效，不需要外部音频文件。不同音效用不同的振荡器波形（方波=射击、锯齿波=爆炸、正弦波=拾取）和频率包络来模拟。BGM 用 setInterval 循环播放简单旋律。这样包体小，且展示了对 Web Audio 的理解。

### Q: 碰撞检测用的什么算法？
A: 圆形碰撞检测（两个圆的圆心距离小于半径之和则碰撞）。比矩形检测更精确，计算量也不大。飞机大战的所有对象（玩家、敌机、子弹、道具）都用圆形碰撞半径。

### Q: TypeScript 在项目中怎么用的？
A: 所有实体都有明确的类型定义，配置对象用 interface 约束，函数参数和返回值都有类型标注。比如敌机类型配置用 EnemyTypeConfig 接口，道具类型用 PowerUpTypeConfig 接口。类型系统在编译时就能捕获很多错误，也让代码更易维护。
